# 링스택 셰이더

> **판단**: 윗면/옆면 톤 분리는 `upFactor` 방식이 맞다. `NdotUp` 3단계 하드컷은
> 그림자 쪽 윗면을 옆면과 같은 톤으로 떨어뜨리므로 되돌리지 말 것.
> **다음**: 윗면 구별 문제가 재현되면 (a) 빌드에 값이 반영됐는지 (b) 카메라 pitch가
> 거의 수평인지 — 이 두 개를 먼저 확인한다. 사용자가 직접 넣은 `_TopThreshold` 하드컷은 유지.

원본 Stack의 깔끔한 룩을 재현하기 위한 커스텀 셰이더.

## ToonNPR.shader

- **목적**: PBR 대신 명암을 뚜렷한 단계로 나누는 카툰풍(NPR) 셰이더.
- **구현**: 방향광 방향과 법선의 내적을 밝음/어두움 2단계로만 나눔. 앰비언트(`SampleSH`)와 옅은 림 라이트를 더해 미니멀하게 표현.
- **윗면/옆면 구분**: `upFactor = saturate(normalWS.y)` 기반 — 윗면은 항상 가장 밝은 톤, 옆면은 빛 받는지 여부로 구분.
- **사용자 수정**: 사용자가 에디터에서 직접 `_TopThreshold` 기반 3단계 하드컷 방식으로 수정함. 셰이더를 다시 만질 때는 이 변경을 덮어쓰지 말 것.

## 윗면/옆면 톤 분리 — 검증값과 기각된 대안

2026-08-14 세션에서 "윗면과 옆면이 구별되지 않는다"를 조사한 기록.

**Unity에서 직접 조회한 값 (당시 정상 확인)**

- 윗면 정점 노멀 = `(0, 1, 0)` / `(0, -1, 0)` — 정확히 수직. 옆벽 노멀과 확실히 분리됨
- 머티리얼 = `_TopTone=1.5`, `_SideLitTone=0.62`, `_ShadowTint=0.4`
- 아이소메트릭 각도(pitch 32°)에서는 허브 흰 원판 → 콜라 밝은 띠 → 콜라 옆벽(어두움)
  → 림 밝은 띠 → 림 옆벽 순으로 단계가 뚜렷이 구별됨

**기각된 대안: `NdotUp` 기준 3단계 하드컷**

`NdotL <= 0`(그림자)을 윗면 판정보다 **먼저** 체크하게 되어, 조명이 닿지 않는 쪽 윗면이
`_ShadowTint`로 떨어져 **그림자 쪽 옆면과 같은 톤이 된다.** 현재 `upFactor` 방식은 윗면이면
조명 방향과 무관하게 항상 `_TopTone`을 유지하는데, 이건 이전 라운드에서 "그림자 쪽에서도
구별되게"라는 요청을 받아 고친 부분이다. 이 대안은 그 수정을 되돌린다.

메시의 각 면 노멀이 정확히 수직/수평으로 갈라져 있고 경사면이 없으므로, `lerp`든
`if`/threshold든 결과는 **수학적으로 동일**하다 — 톤이 안 갈리는 건 로직 문제가 아니다.

**미해결 (confidence: low)**

위 검증 후에도 화면상 구별이 안 된다는 보고가 이어졌고, 원인이 확정되지 않았다. 가설:
(a) 강화된 값이 아직 반영되지 않은 빌드를 보고 있었다, (b) 촬영 각도가 거의 수평
(grazing angle)이라 윗면 폭이 화면상 0에 가깝게 눌렸다.

> **주의 — 위 "사용자 수정" 항목과의 긴장 관계**: 사용자가 직접 넣은 `_TopThreshold`
> 3단계 하드컷은 덮어쓰지 않아야 하지만, **그 방식의 알려진 단점이 바로 여기 기록된
> 그림자 쪽 윗면 문제다.** 셰이더를 다시 만질 때 둘 다 알고 있어야 한다.

## TranslucentUnlit.shader

- **목적**: 반투명 정렬 가이드 라인용 Unlit 셰이더.
- **구현**: `Blend SrcAlpha OneMinusSrcAlpha`, `ZWrite Off`, `Cull Back`.
