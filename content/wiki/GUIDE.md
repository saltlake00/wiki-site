# LLM 위키 사용 가이드 (GUIDE)

> **이 파일을 먼저 읽어라.** 이 위키는 AI 에이전트가 유지보수하는 지식 베이스다.
> 위키 전체를 읽지 말고, 이 가이드 → `index.md`(목차) → 필요한 페이지만 읽어라.

## 이 위키가 뭔가

카파시(Karpathy)의 LLM Wiki 패턴을 개인 지식 베이스로 구축한 것.
RAG처럼 매번 검색하지 않고, 지식을 **한 번 정리해서 계속 갱신**한다.
도메인: 일상 업무, 개인 취미, 프로그램 개발, LLM 사용 기록.

## 폴더 구조

```
wiki/
├── GUIDE.md              # ← 이 파일. AI가 먼저 읽는 지침서
├── SCHEMA.md             # 규칙, 태그 분류, frontmatter 형식
├── index.md              # 모든 페이지의 한 줄 요약 (목차)
├── log.md                # 활동 기록 (append-only)
├── raw/                  # 원본 자료 (불변, 수정 금지)
│   └── <도메인>/<하위>/<항목>/
├── projects/             # 프로젝트 도메인
│   └── <분야>/<프로젝트명>/
├── llm/                  # LLM 사용 기록 도메인
├── concepts/             # 공통 개념 (여러 도메인에 걸친 것만)
├── comparisons/          # 공통 비교
└── queries/              # 저장할 가치 있는 질문 결과
```

## 다른 기기에서 사용/편집하기

이 위키는 **Google Drive에 있어서, 같은 구글 계정으로 Drive를 연결한 모든 기기에서 자동 동기화**된다. 편집도 가능하다.

### 기기별 설정

| 기기 | 설정 방법 |
|------|-----------|
| **이 PC (Windows)** | Google Drive 데스크톱 → `G:\내 드라이브\wiki` (이미 설정됨) |
| **다른 PC** | Google Drive 데스크톱 설치 → 같은 구글 계정 로그인 → `내 드라이브\wiki` 자동 동기화 → Obsidian으로 열기 |
| **모바일 (iOS/Android)** | Google Drive 앱 + Obsidian 앱 설치 → 같은 계정 로그인 → Drive의 `wiki` 폴더를 vault로 열기 |
| **다른 AI 에이전트** | 위키 폴더를 주고 "`GUIDE.md` 먼저 읽고 규칙대로 다뤄줘" |

### 편집 시 충돌 방지 규칙 (중요)

- **한 번에 한 기기에서만 편집**한다. 동시에 두 기기에서 같은 파일을 편집하면 충돌한다.
- 모바일에서 편집한 내용은 **Drive 동기화가 끝난 뒤에** PC에 반영된다. 저장 직후 바로 PC에서 열면 이전 버전이 보일 수 있다.
- **Git은 백업/버전관리용**이다. 편집 후 가끔 `git add -A && git commit && git push`로 백업한다.
- **이미지**는 Git에 커밋하지 않는다. `raw/assets/`에 두고 Drive로만 동기화한다.

### Hermes에서 자동 사용

Hermes는 `WIKI_PATH` 환경변수(`.env`)로 이 위키를 인식한다. Hermes 세션에서 "위키에 정리해줘"라고 하면 자동으로 이 위키를 사용한다.

## 작업 전 반드시 (오리엔테이션)

새 세션에서 위키를 다루기 전에 **항상** 이 3개를 읽어라:
1. `SCHEMA.md` — 규칙과 태그 분류 파악
2. `index.md` — 어떤 페이지가 있는지 파악 (중복 방지)
3. `log.md` 최근 항목 — 최근 활동 파악

이걸 건너뛰면 중복 페이지 생성, 교차참조 누락, 규칙 위반이 발생한다.

## 페이지 추가/수정 규칙

- **새 프로젝트**: `projects/<분야>/<프로젝트명>/` 폴더를 만들고 그 안에 페이지를 넣는다.
- **LLM 사용 기록**: `llm/사용로그.md`에 append-only로 쌓는다.
- **공통 개념**: 여러 도메인에 걸쳐 쓰이는 것만 `concepts/`에 넣는다.
- **모든 페이지**:
  - YAML frontmatter 필수 (`title`, `created`, `updated`, `type`, `tags`, `sources`)
  - `[[위키링크]]`로 최소 2개 이상 다른 페이지와 연결
  - 태그는 `SCHEMA.md`의 분류에서만 사용
  - 수정 시 `updated` 날짜 갱신
- **원본 자료**: `raw/`에 저장하고 **절대 수정하지 않는다** (불변). 수정은 위키 페이지에서.
- **완료 후**: `index.md`에 추가 + `log.md`에 기록.

## 조회 방법

1. `index.md` 읽어 관련 페이지 찾기
2. 필요한 페이지만 `read_file`로 읽기
3. 답변 시 출처 페이지를 `[[위키링크]]`로 인용
4. 가치 있는 답변은 `queries/`에 저장

## 점검 (lint)

사용자가 "위키 점검해줘"라고 하면:
- 고아 페이지 (들어오는 링크 없는 페이지)
- 깨진 `[[위키링크]]`
- index.md에 없는 페이지
- frontmatter 누락/태그 분류 위반
- 90일 이상 갱신 안 된 페이지
- 모순(contradiction) 표시된 페이지
- log.md 500줄 초과 시 회전

## 태그 분류 (요약)

- **업무**: 업무, 회의, 프로젝트, 문서, 커뮤니케이션
- **개발**: 개발, 프로그래밍, 언어, 프레임워크, 도구, 알고리즘, DB, 보안, DevOps, AI/ML
- **취미**: 취미, 게임, 음악, 영화, 독서, 운동, 요리, 여행
- **개인**: 건강, 재정, 습관, 목표, 일상
- **메타**: 비교, 타임라인, 논쟁, 예측, 리뷰

자세한 규칙은 `SCHEMA.md` 참고.
